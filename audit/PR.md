# Fix audited mechanics and implement ten missing item rules

Repairs the six failing audit scenarios: Mordren’s ordinary damage handling, four summon-card placement paths, and repeated Q001 completion deducting Gold again. Implements the ten previously blocked item mechanics, with shared browser/server rules for Rest, Lockpick Search/Interact, extra turns, Rapid Fire/reload, Worldheart stances/cooldown refresh, terrain bonuses, Stagger Saves, Travel Encounter rerolls and Crystal crafting substitution. EQ116 retains its existing tested Channel replacement and has its stale diagnostic corrected.

Also fixes Staggered’s documented next-Attack penalty and runtime Hero Attack lookup used by Enemy targeting. Real two-client regressions cover Rest synchronization, Rapid Fire damage before final-Action turn handoff, and Night’s Whisper’s full extra turn. Server-owned state tracks ownership, replay protection, pending actions and saved roll choices. Snapshot application cannot echo authoritative Health changes back as local damage/healing; remote phase changes require the room’s resolution token even during startup. Ordinary Basic Attacks retain authority until their final-Action combat settles. The obsolete remote snapshot watcher is disabled so server updates do not trigger a continuing cycle of compatibility snapshots. Root and served public copies match; the service worker cache includes the new runtime modules.

EQ044 uses the explicitly approved **+2 Attack on the first Attack each encounter** in the automatic-hit combat system. Other previously undefined rule defaults are listed in [audit/IMPLEMENTED_RULES.md](audit/IMPLEMENTED_RULES.md), including the 4+ Stagger Save, Rest baseline and three-use Rapid Fire magazine. These balance defaults need review before merging.

Validation: **43 foundation tests and 183 browser scenarios passed**, with 0 failures or skips in the final complete rerun (Node 24.19.0, Playwright 1.64.1, Chromium 154). `npm run audit:coverage` returns the expected failure for 657 records without exhaustive effect certification. Detailed expected/actual results are recorded in audit/REPORT.md, audit/VALIDATION.md and audit/execution.json. The missing historical runners were not recovered; the new checked-in foundation and stability runners are clearly labeled replacements. The strict exhaustive-effect coverage gate remains failing: named passing scenarios do not certify every branch of all 323 cards, 144 equipment and 190 loot records, all level abilities or every campaign. The first hosted run exposed two startup-order failures (Bloodrage and Orb/Rest). The follow-up gates mechanics startup on its required runtime layers, advances local extra-turn counters independently, and waits for gameplay readiness in fixtures. The complete local rerun again passes 183 scenarios; hosted revalidation of this follow-up is pending. CI preserves both browser result files, the foundation log and explicit command outcomes. Fresh-task environment restoration is not claimed.

This draft is stacked on audit PR #1 (base: testing/mechanics-audit-33621). All functional tests use localhost servers, temporary persistence directories and isolated accounts/browser contexts. No production/staging player data, Render configuration, deployments or merges are changed.
